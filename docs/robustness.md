# 扰动鲁棒性：亮度能救、噪声伤在聚合、模糊救不回来

> 目的：回答面试里那句「你的模型换个光照/相机/对焦还行吗？」
> 全部实测，单类（screw）单 seed，协议见 §2；配图与逐图分数在 `experiment_data/01_mvtec_gpu/results_gpu_robust/`。

## 1. 一句话结论

同一套记忆库，只把**测试图**做扰动、阈值分别取「冻结」与「重标定」：

- **亮度 ×0.8**：排序几乎不坏（image AUROC 0.9553 → 0.9492），重标定后判定与干净时一致（召回 26.9%、过杀 0%）。**可救。**
- **加性噪声 σ=0.05/0.10**：image AUROC 塌到 **0.7387 / 0.4782**（后者已低于随机），重标定只能把过杀压回 4.9%/19.5%，召回掉到 33.6%/24.4%。**排序坏了，救不回。**
- **模糊 σ=1 px**：image AUROC **0.4583**，重标定把阈值抬到 59（干净时 43），结果召回只剩 **1.7%**。**完全不可用。**

三者都稳定：`pixel AUROC` 只从 0.9845 掉到 0.9383–0.9626，说明**定位信息还在，坏的是「图像级怎么汇总」这一步**。

## 2. 协议

| 项 | 值 |
|---|---|
| 类别 | screw（15 类里最难：干净时召回仅 26.9%） |
| 建库 | 224 张良品，greedy coreset k=2000，`size=320`，WR50-timm，`blur_sigma=2` |
| 标定 | 96 张良品（`--calib-ratio 0.3`），阈值取 P99 |
| 测试 | 160 张（89 良品 + 71 缺陷），扰动施加于测试图 |
| 冻结 | 阈值来自**干净**标定图；扰动只作用于测试 |
| 重标定 | `--perturb-calibration`：标定图也加同样扰动、重算阈值 |
| 扰动实现 | `perturb_img()`：亮度乘系数、加性高斯噪声（0–1 尺度）、高斯模糊；固定 `seed` 可复现 |

## 3. 结果

召回/过杀为判定结果（阈值 P99），AUROC 与阈值无关，所以两组共用同一列 AUROC。

| 扰动 | image AUROC | pixel AUROC | 冻结阈值 召回 / 过杀 | 重标定 召回 / 过杀 | 重标定阈值 |
|---|---:|---:|---:|---:|---:|
| 无（基线） | 0.9553 | 0.9845 | 26.9% / 0.0% | — | 42.98 |
| 亮度 ×0.8 | 0.9492 | 0.9825 | 23.5% / 0.0% | **26.9% / 0.0%** | 42.77 |
| 噪声 σ=0.05 | 0.7387 | 0.9626 | 100% / **100%** | 33.6% / 4.9% | 50.46 |
| 噪声 σ=0.10 | 0.4782 | 0.9507 | 100% / **100%** | 24.4% / 19.5% | 58.47 |
| 模糊 σ=1 px | **0.4583** | 0.9383 | 100% / **100%** | **1.7% / 4.9%** | 59.08 |

「冻结」列出现 100%/100% 不是巧合：扰动把**良品**的分数整体抬过阈值，于是全判 NG（过杀 100%），缺陷自然也「全召回」。这正是产线上最常见的失效形态——**不是漏检，而是全线报警**。

## 4. 四条判断

1. **亮度是乘性、低频的，模型对它近乎不变。** 特征层的对比度归一化吃掉了大部分增益变化；剩下的是阈值位置问题，用标定图重标即可。这类扰动**不值得单独做数据增强**。
2. **噪声打在 `max` 聚合上，是结构性弱点。** 图像分数取「所有 patch 分数的最大值」，而加性噪声在 40×40 的 patch 网格里总能贡献一个高的尾值——良品的 max 被噪声顶起来，排序就崩了。pixel AUROC 只掉 2 点是反证：**每个 patch 的分数仍然可信，坏在「取最大值」这个聚合**。
   - 面试讲法：`max` 聚合对稀疏小缺陷最敏感，代价是**一个噪声像素就能决定整张图的分数**；要抗噪就得换 top-k 均值 / 分位数，或先做去噪前置（本文的 `blur_sigma=2` 只够压高频纹理，压不住随机噪声）。
3. **模糊不可救，因为它是信息删除。** σ=1 px 在 320 输入上等于把瑕疵边缘抹掉一个像素级台阶；排序直接掉到 0.4583。重标定把阈值抬到 59 是「标定图也被模糊了，良品分数整体上移」的副作用——结果缺陷分数全在阈值下，召回 1.7%。
4. **鲁棒性要按「失效形态」报，不是按 AUROC 报。** 三种扰动的 AUROC 分别是 −0.6 / −21.7 / −49.7 点，但产线关心的是：亮度 → 需重标定；噪声 → 全线报警 + 召回崩；模糊 → 静默漏检。**同一句「鲁棒性一般」掩盖了三种完全不同的处置方式。**

## 5. 部署建议（写给自己和面试官）

1. **先查来料**，再谈模型：对焦（轻微模糊就致命）、照明（可重标定）、传感器噪声（结构性）。
2. 若噪声是常态：把 `score_agg` 从 `max` 换成 top-k 均值或 P99.5 分位，再配 `blur_sigma`；这属于**改聚合**，不是改模型。
3. 阈值**必须能在线重标定**（本项目的 `--calib-ratio` + P99 就是为此设计的），否则换批次就会全线报警。
4. 上线前做一次「扰动矩阵」小实验（本文这张表），把可接受区间写进 SOP。

## 7. 局限

- **单类 + 单 seed**：screw 是最难类，结论对「噪声伤 max 聚合」应可推广，但别的类数值会不同。
- 噪声是**加性高斯**，不是真实传感器噪声（后者含读出噪声、固定模式噪声）；模糊用固定 σ，未模拟离焦的空间变化。
- 「重标定」只换了阈值，**没有重训/重抽 coreset**；真实产线换批次时记忆库也要换。
- 未测 JPEG 压缩、色偏、镜头污渍等；不测不代表不会出事。
- 判定口径为 image 级 P99；产线若用灰区三档，噪声下复核量会先爆（这是更早的失效信号）。
