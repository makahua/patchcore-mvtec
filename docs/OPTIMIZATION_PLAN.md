# PatchCore 面试项目执行计划

- 制定日期：2026-11-06
- 项目：`patchcore-mvtec`
- 状态：计划稿，尚未启动本计划中的实验
- 目标：先把结果做可信，再决定是否改默认。
- 主阈值：`fpr=0.005`；算法段时延门槛：25 ms。
- 原则：先冻结协议，再运行实验；`layer1+2` 和鲁棒聚合均须通过验收后才能进入默认配置。

## 一、冻结实验协议

先固定配置、验收规则和数据清单，再运行实验。

| 项目 | 固定值 |
|---|---|
| 权重 | 现有 timm `racm_in1k`，核验文件 SHA256 |
| 输入 | 320×320，stretch，不做 ImageNet 归一化 |
| 记忆库 | legacy greedy，先抽取 10% 候选，再选最多 2000 个中心 |
| 特征对照 | `2+3` 对 `1+2` |
| 分数处理 | 高斯平滑 σ=2，图像聚合 `max` |
| 良品划分 | 70% 建库、30% calibration，`split-seed=42` |
| 重复次数 | coreset seed 0、1、2 |
| 主判定口径 | 经验 P99.5，`fpr=0.005`，灰区倍数 1.2 |
| 次判定口径 | P99，仅用于连接历史结果和敏感性分析 |
| 精度与批量 | FP32、batch=1 |
| 数据角色 | MVTec development-only |

三个 seed 共用完全相同的建库、标定、测试清单，改变 coreset 随机性。所有参数显式记录，不依赖脚本默认值。除 Git commit 外，保存实际运行源码的哈希，防止未提交代码导致记录失真。

### 三档判定定义

- `score < thr_ok`：OK。
- `thr_ok ≤ score < thr_ng`：REVIEW。
- `score ≥ thr_ng`：NG。
- `thr_ok` 由该运行的 calibration 良品分数计算。
- `thr_ng = thr_ok × 1.2`。

这里的名义 `fpr=0.005` 对应**超过 OK 阈值的比例，即 REVIEW+NG**；“过杀率”另定义为良品被判 NG 的比例。二者不能混称。

P99.5 是可计算的经验分位，但现有标定样本量不足以提供 0.5% 的有限样本 conformal 保证。conformal 单独报告可达水平；bootstrap 用于描述敏感性，不替代保证。

## 二、先补实验产物，再跑 15 类配对基线

开跑前只补必要的实验支持：

- 通过 `tools/run_experiment.py` 生成配置、逐图分数、指标、汇总、计时和日志。
- 每个运行保存像素分数图，调用现有 AUPRO 工具计算区域指标。
- 保存记忆库及其配置，供后续扰动实验复用，避免每种聚合重新建库。
- 校验 train/calibration 不相交、类别齐全、三个 seed 清单一致。
- 单类别单进程运行，记录 CPU 内存峰值、GPU 峰值和阶段进度。

先按实际训练图数量和特征张量大小，选出内存需求最大的类别，再加 screw 做两个层组合的 smoke。通过后扩到全量。

完整验收矩阵为：

> **15 类 × 3 seed × 2 层组合 = 90 个类别运行。**

已有运行只有在源码相关行为、权重、样本顺序、划分、预处理、coreset、平滑和评测口径全部匹配时才复用。缺少 AUPRO 就补齐；无法确认一致就重跑。

**任何类别或 seed 缺失，都不能宣布完成“15 类、3 seed”验收。** 已完成部分可以报告，但不据此切换默认。

## 三、按统一方式统计，决定是否扶正 layer1+2

每个 seed 先计算 15 类 macro，再对三个 macro 计算均值和样本标准差，使用 `ddof=1`。这个标准差描述 coreset 随机性，不代表独立测试集不确定性。

每个 seed 分别计算 pooled AUROC，再汇总；不把三个 seed 的重复测试图片拼成一个更大的样本集。

### 必须交付的结果

| 维度 | 报告内容 |
|---|---|
| 排序质量 | 逐类 image/pixel AUROC、macro、pooled |
| 定位质量 | 逐类及 macro AUPRO@30%、AUPRO@10% |
| 三档判定 | 漏检、实际 NG 过杀、良品复核、总体复核；附分子/分母 |
| 配对收益 | 每个 seed 的 `1+2 − 2+3`，以及差值均值、范围 |
| 资源代价 | 建库时间、CPU/GPU 峰值、算法段时延 |
| 完整性 | 15 类 × 3 seed 覆盖表、失败及重跑记录 |

### 默认切换门槛

下列门槛开跑后不更改：

| 门槛 | 通过条件 |
|---|---|
| 完整性 | 两组都完成 15 类 × 3 seed |
| 总体质量 | macro image AUROC、macro AUPRO@30% 的配对均值差均 ≥0 |
| 单类退化 | 任一类别的三 seed 平均 image AUROC 或 AUPRO@30% 下降不得超过 0.03 |
| 算法时延 | 同设备、FP32、batch=1，15 类算法段均值 ≤25 ms |

时延用独立的配对基准测量：充分预热、相同图片、两组交替执行，GPU 同步后计时；同时报告逐类和 P95。读图、解码、缩放及数据传输另列，避免混入算法段。

另外增加一道**业务保护条件**：如果主口径下 macro 漏检或实际 NG 过杀上升，暂不切换默认，先给出收益与代价的说明。排序指标改善不能直接写成漏检改善。

若失败，交付结论就是“候选方案在哪些类别有效、在哪项门槛失败”，保留原默认。若成功，再统一更新实验入口、CLI 和 GUI。

## 四、默认配置与历史结果的处理

`classify.py` 的建库、推理、评测和 GUI 都按记忆库元数据加载层组合、归一化、聚合及阈值配置，避免实验入口与演示入口使用不同模型。

旧 bank 保持可读：能够确认来源和维度的旧格式按 `2+3` 加载；只有配置缺失且无法判定，或元数据与维度矛盾时才拒绝。测试覆盖新旧格式及错误配置。

README 的主表换成新协议的完整结果。旧 0.9805、screw 0.9553 保留为**历史快照**，未知的 commit、split-seed 等字段明确写“未归档”，不补猜测值。

CI 保留旧快照的复算检查，并为新主结果增加独立检查。当前 CI 读取的是旧 `results_best/scores`，因此不能只把预期数字替换成新结果。

## 五、只做一个新方向：鲁棒聚合

第 0 步选定层组合后，固定记忆库、权重、平滑、划分和阈值规则，只改变图像分数聚合。

### 实验矩阵

先做 screw、pill、toothbrush，三个 seed，以下固定条件：

| 扰动 | 聚合 |
|---|---|
| 干净、亮度×0.8、噪声σ=0.05、噪声σ=0.10、模糊1 px | max、top1%、top5%、top10%、截尾均值 |

截尾均值固定为：**去掉最高约 1% patch，取最高 10% 中剩余部分的均值**，明确整数取整规则。

每个条件只提取一次 patch 分数图，同时计算五种聚合。保存 calibration 和 test 的 FP32 分数图；不同聚合使用相同噪声样本，扰动随机种子独立固定。

每种聚合都报告两套结果：

- 干净 calibration 标定，阈值冻结后应用于扰动图。
- 同条件 calibration 重新标定后应用于扰动图。

### 筛查与验收

预先采用以下筛查标准：噪声 σ=0.10 下至少两个重点类别 AUROC 提升 ≥0.03，三个类别干净 AUROC 均不下降超过 0.01。通过者全部进入 15 类核验，核验只跑干净和 σ=0.10。

15 类核验要求：

- 噪声 macro AUROC 提升 ≥0.03。
- 冻结阈值下 macro 缺陷检出率提升 ≥5 个百分点。
- 干净 macro AUROC 下降 ≤0.01。
- 实际 NG 过杀不增加。

若多个候选通过，按预先固定的噪声 macro AUROC 排序选择，并报告全部候选结果。

只在重标定后改善的方案，结论限定为“重标定条件下有效”。模糊实验如实报告新结果，不沿用旧配置的 1.7% 召回，也不预设聚合一定无效或一定能救。

## 六、锁定配置复验与演示

### split-seed 123 复验

最终配置确定后，换 `split-seed=123`，运行三个 coreset seed。

建议同时跑**原基线与最终配置**，这样才能判断整体收益是否在另一划分下保持；只跑最终配置只能说明其绝对指标对划分是否敏感。此次配置和判定规则不再调整，阈值数值仍由新划分的 calibration 按同一规则计算。

结果单独展示，仍称为划分敏感性复验。VisA PCB2 保留旧配置的一次已揭盲检查，不作为新配置的外部验证成绩。

### 面试演示

演示沿用现有文件夹推理入口，输出每图异常分数、双阈值、判定、热力图及 CSV/JSON 汇总。

最终配置重新测量真实 700²、900²、1024² 输入的算法段和端到端时延，报告预热后的中位数、P95。历史性能数字不搬到新配置名下。

## 七、排期、停止条件与范围

| 阶段 | 排期方式 |
|---|---|
| 协议、产物支持、smoke | 第 1 天 |
| 15 类配对基线与验收 | 根据 smoke 实测排期，优先完成 |
| 鲁棒聚合 | 基线完成后安排约 2–3 天，再按实测修正 |
| split-seed 123 复验 | 配置锁定后安排 |
| 演示与必要重构 | 最后 1–2 天 |

48 小时作为**第 0 步的目标窗口**，不承诺届时一定通过。现有 `2+3` 全 15 类单 seed 约 41 分钟，三 seed 约两小时；候选层、AUPRO 和资源余量需由 smoke 补充估算。

运行中若持续换页并且进度停滞，或阶段耗时显著超出 smoke 预测，停止该运行并保留记录。资源失败、未完成和指标失败分别标注。

裁剪仅在最终配置的 screw 工作点仍不满足要求时另立实验；届时必须使用实际网格尺寸，并对完整裁剪融合流程重新标定。投影 coreset 也作为后续独立对照。

当前范围不加入 ensemble、`1+2+3`、默认九邻域或新的部署后端。

## 最终交付标准

最终交付应能明确回答：

1. 改了什么。
2. 15 类三个 seed 得到了什么。
3. 相比同协议基线提升多少。
4. 付出多少资源。
5. 哪些结果仍然只属于开发分析。
