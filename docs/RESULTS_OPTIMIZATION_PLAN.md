# PatchCore 结果优化计划

日期：2026-11-03（2026-11-04 复核：本机解释器为 Python 3.13.9，命令中的 `python` 应改为 `.venv\Scripts\python.exe`；`--data E:/MVTec` 应改为 `--data MVTec/mvtech_anomaly_detection`，原因见 `docs/REPRODUCE.md`）

## 目标与现状

当前主配置为 `greedy=2000, size=320`：MVTec AD 15 类宏平均 image AUROC 0.9805、pixel AUROC 0.9709，平均推理与最近邻评分约 19.7 ms（**算法段**：不含读图与 PNG 解码；端到端 900² 42.2 ms、1024² 62.4 ms，见 `docs/latency-breakdown.md`），峰值显存约 190 MB。核心瓶颈已不是整体排序能力，而是少数难类在固定阈值下的漏检，以及低误报率估计缺少足够标定样本。

已有结果显示，名义 0.5% 过杀工作点下宏平均召回约 82.8%；每类标定良品只有 18–117 张，因此不能把该工作点解释为产线保证。`experiment_data/00_baselines/results_neigh/` 的 grid 单类实验也显示 9 邻域配置明显增加时延和显存且该类 AUROC 下降，不作为默认优化方向。

## 优先级与验收

### P0：锁定可比较的实验协议

- 固定权重、输入尺寸、数据清单、划分、随机种子和设备；每个配置写入独立结果目录。
- 保持 MVTec 类别内宏平均与 pooled 指标分开报告；同时报告逐类 image/pixel AUROC、召回、误报、时延和显存。
- 阈值只由留出的良品 calibration 集确定。记录 calibration 样本量及误报的实际分子/分母；小样本下不声称达到 0.5% 的统计保证。
- 对照组使用当前 `experiment_data/00_baselines/results_best/` 主配置。先比较单变量，避免把效果归因到错误因素。

### P1：少样本记忆库曲线（代码已实现；screw 首轮实验已完成）

回答“只有少量正常样本时效果如何”。选 `bottle`（较易）、`screw`（细小缺陷）、`grid`（纹理）三个代表类，建库图数取 5、10、20、50、100、全部；calibration 图不计入建库数。每档使用至少 5 个预先声明的 seed，并汇报均值及标准差/区间。

参数 `--train-limit` 已加入 `patchcore_demo.py`。每次运行用单独输出目录；seed 同时控制 calibration 划分与建库抽样（建库抽样使用 `seed + 1`），避免总取文件名靠前的样本。

命令示例：

```powershell
python patchcore_demo.py --data E:/MVTec --category screw --size 320 --greedy 2000 --calib-ratio 0.3 --train-limit 10 --seed 0 --weights torch_cache/wide_resnet50_2_timm.pth --out experiment_data/01_mvtec_gpu/results_fewshot/screw_n10_s0
```

验收：保存配置与每类结果；生成按建库图数绘制的 image/pixel AUROC 和固定良品誤報目標下召回曲线。不得把单 seed 或测试集上选出的最佳点当成结论。

### P1：难类小缺陷与平滑消融（screw 已完成首轮，多类别复验待做）

聚焦 `screw`、`toothbrush`、`pill`、`grid`，对照 `--blur-sigma 0, 0.5, 1, 1.5, 2`，先在固定 320 配置下比较；若小缺陷仍被漏掉，再单独比较 320 与更高分辨率。关注逐类 image AUROC、pixel AUROC、PRO（若已实现）、固定阈值漏检和热力图，记录时延/显存。

命令示例：

```powershell
python patchcore_demo.py --data E:/MVTec --category screw --size 320 --greedy 2000 --calib-ratio 0.3 --blur-sigma 0.5 --seed 0 --weights torch_cache/wide_resnet50_2_timm.pth --out experiment_data/01_mvtec_gpu/results_blur/screw_sigma05
```

验收：同一数据划分比较各 sigma；若声称改善，至少跨 3 个 seed 复现。平滑关闭可能增加噪点，分辨率提高会增加资源成本，因此按召回、定位质量和节拍共同决策。

### P1：阈值工作点可靠性

从独立采集或预留的良品数据扩大每类 calibration 集，并保留独立 test。报告目标误报率下实际误报数量/样本总数、缺陷召回和复核比例；以 bootstrap 或多次独立划分呈现阈值波动。若每类良品数量仍不足以支撑极低误报目标，应明确标记证据不足，而不是靠调高分位数制造“达标”数字。

验收：给出误报率—漏检率—复核量曲线，并在一批未参与建库、调参和阈值选择的新样品上复核。

### P2：采集变化鲁棒性

在冻结阈值条件下逐项测亮度变化、噪声、轻微模糊、旋转和压缩；另用独立良品重标定后测恢复效果。几何变换需同步变换 mask。记录每种扰动的参数、seed、逐类指标和资源，不在扰动 test 标签上调阈值。

验收：冻结阈值与重新标定两组结果分开报告，说明哪些变化可以靠重新标定恢复、哪些需要改善采集或模型。

## 决策规则

1. 先确保对照公平、口径一致，再谈“提升”。
2. 主目标优先使用固定误报条件下的缺陷召回和小缺陷定位；AUROC 作为排序指标补充。
3. 只有跨 seed / 独立样品稳定且资源成本符合节拍的变化才进入默认配置。
4. 记录负结果。当前 9 邻域实验已说明增加复杂度不必然提升性能。

## 已实施的代码改动

- `patchcore_demo.py` 新增 `--train-limit`，按 seed 随机抽取建库图，calibration 图片不计入限额。
- 新增 `--blur-sigma`（默认 2.0，0 表示关闭平滑），在 calibration 与 test 评分中使用相同设置。
- CSV 行与逐图 JSON 记录平滑参数、少样本数量和抽样 seed，便于结果追溯。

首轮 GPU 实验结果和限制见下节；单 seed 候选结果尚不足以调整默认配置。

## 首轮 GPU 实验记录（2026-11-03）

设备为 RTX 3050 Laptop 4 GB，PyTorch 2.7.0+cu128；类别为 screw，size=320、greedy=2000、calib-ratio=0.3、thr-pct=99、权重 `wide_resnet50_2_timm.pth`。逐次结果保存在 `experiment_data/01_mvtec_gpu/results_gpu_blur/` 和 `experiment_data/01_mvtec_gpu/results_gpu_fewshot/`。

### screw 平滑参数（单 seed=0）

| sigma | image AUROC | pixel AUROC | threshold 下召回 | 良品误报率 | 延迟 |
|---:|---:|---:|---:|---:|---:|
| 0.0 | 0.9158 | 0.9788 | 5.04% | 0.00% | 18.70 ms |
| 0.5 | 0.9326 | 0.9844 | 5.04% | 0.00% | 17.23 ms |
| 1.0 | 0.9543 | **0.9868** | 17.65% | 0.00% | 17.24 ms |
| 2.0 | **0.9553** | 0.9845 | **26.89%** | 0.00% | 17.20 ms |

在这次固定划分上，sigma=1 的 pixel AUROC 最高，sigma=2 的排序 AUROC 与固定阈值召回最高；因此若优先 screw 图像级召回，sigma=2 是值得复验的候选，若优先像素定位则 sigma=1 是候选。各 sigma 的 threshold 都由对应 calibration 分数重新计算，当前测试良品样本有限，观测 0% 误报不代表真实误报为零。此组只有一个 seed，不能据此改全局默认值。

| 建库图数 | seed | image AUROC | pixel AUROC | threshold 下召回 | 良品误报率 |
|---:|---:|---:|---:|---:|---:|
| 5 | 0 | 0.5862 | 0.9502 | 2.52% | 2.44% |

当前小样本结果较差且 seed 波动明显，不能支持“少量良品足够”的结论。这里的 5/20 指校准划分之后用于建库的图数；每次仍使用额外留出的 96 张良品做校准。当时尚需补 10/50/100/全量档与更多 seed；这些档位的后续结果见“后续顺序执行结果”。

### 后续顺序执行结果

**sigma 复验**：sigma=1、2 各追加 seed 1、2，与前面的 seed 0 合并为 3 次。sigma=1 的 image AUROC 为 0.9449±0.0102、pixel AUROC 0.9867，阈值召回均值 29.69%（范围 17.65–42.02%）；sigma=2 分别为 0.9451±0.0106、0.9843、37.82%（范围 26.89–43.70%）。sigma=2 在 screw 的阈值召回更高，但 sigma=1 像素 AUROC 更高。因为只有 3 个 seed，且 seed 同时改变训练/校准划分，暂不改变全局默认 sigma。

**扩大校准划分**：screw 从 30%（96 张 calibration、224 张建库）增至 50%（160 张 calibration、160 张建库），seed 0/1 的 image AUROC 为 0.9143/0.9217，pixel AUROC 均为 0.9840，阈值召回为 29.41%/41.18%。这与 30% 比较同时改变了可用建库图数，因此不能把差异只归因于校准集；增加校准样本的同时，建库覆盖下降。该数据规模仍不足以可靠声明 0.5% 真实过杀率。

**少样本曲线**：screw 每档 5 个 seed；各次固定同一 160 张测试图，seed 改变训练/校准划分。均值±seed 标准差如下：

| 建库图数 | image AUROC | pixel AUROC | 阈值召回 | 误报率 |
|---:|---:|---:|---:|---:|
| 5 | 0.5323±0.0629 | 0.9432±0.0105 | 3.53%±2.62% | 0.98%±1.34% |
| 10 | 0.5572±0.0566 | 0.9581±0.0024 | 1.01%±1.10% | 0.00%±0.00% |
| 20 | 0.6478±0.0418 | 0.9681±0.0031 | 3.53%±2.17% | 0.49%±1.09% |
| 50 | 0.7433±0.0429 | 0.9776±0.0029 | 7.23%±5.40% | 1.46%±2.18% |
| 100 | 0.8781±0.0177 | 0.9830±0.0011 | 20.84%±13.29% | 0.98%±2.18% |
| 全量（224） | 0.9454±0.0081 | 0.9837±0.0012 | 45.38%±12.42% | 0.98%±1.34% |

AUROC 随建库图数整体提高，但阈值召回 seed 波动很大。曲线支持“更多正常样本改善排序表现”，不支持“100 张足以可靠检出”。同一测试集被用于多轮方案探索，以上数字属于探索性分析；最终泛化结论需在未参与本轮探索的新样品上验证。

为隔离“建库样本数”与 calibration 划分的影响，又追加了固定 `split_seed=42` 的曲线；每档 3 个建库/coreset seed，共用完全相同的 96 张 calibration 与 160 张 test 图：

| 建库图数 | image AUROC | pixel AUROC | 阈值召回 | 误报率 |
|---:|---:|---:|---:|---:|
| 5 | 0.5082±0.0416 | 0.9450±0.0016 | 2.52%±1.45% | 2.44%±2.44% |
| 20 | 0.6209±0.0476 | 0.9688±0.0019 | 5.60%±4.78% | 4.07%±5.08% |
| 50 | 0.7429±0.0360 | 0.9767±0.0028 | 17.93%±5.96% | 4.07%±5.08% |
| 100 | 0.8865±0.0116 | 0.9829±0.0001 | 49.02%±5.90% | 1.63%±2.82% |
| 224 | 0.9231±0.0065 | 0.9840±0.0017 | 66.67%±4.23% | 4.88%±2.44% |

固定 calibration 后，增加建库图片对排序/召回的趋势更清晰；但良品误报仍很不稳定。这不是矛盾：阈值取自 96 张良品的 P99，尾部实际上由极少数样本决定；测试良品也只有 41 张，误报率只能以约 2.44 个百分点的步长变化。该曲线仍复用了 MVTec test，只作开发分析。

**采集变化鲁棒性（screw，seed=0）**：brightness ×0.8 与输入模糊 sigma=1 px 各比较冻结阈值和扰动良品重标定。冻结阈值时，亮度变化 image/pixel AUROC 为 0.9492/0.9825，召回 23.53%、误报 0%；重新标定后 AUROC 不变，召回回到 26.89%、误报 0%。轻度模糊时，冻结阈值 image/pixel AUROC 降至 0.4583/0.9383，召回 100% 但误报也 100%；扰动良品重标定后排序 AUROC 不变，召回 1.68%、误报 4.88%。模糊造成的排序退化无法靠阈值重标定修复，需考虑采集对焦、训练覆盖或模型适配。每个扰动只有一个 seed，结果仅用于定位风险。

代码通过 `--perturb-brightness`、`--perturb-noise`、`--perturb-blur` 设置确定性非几何扰动；默认仅扰动测试图，保持 clean calibration 阈值冻结；加 `--perturb-calibration` 则使用同一扰动重新标定。当前已完成亮度和模糊，不代表已覆盖噪声、姿态或其他类别。

**锁定配置外部检查**：按 `docs/EXPERIMENT_PROTOCOL.md` 的冻结配置在 VisA PCB2 上运行一次：631 张建库、270 张 calibration、200 张 test；image AUROC 0.8794、pixel AUROC 0.9766、阈值召回 41.0%、误报率 3.0%、推理 18.43 ms/张，建库耗时 706.9 秒。PCB2 现已使用，不能再作为之后实验的独立 holdout。
