# 表征与几何试点：PCA / unfold-pool / crop-zoom

> 目标：定位「我们 0.9830 与官方 IM224 复刻 0.9872 之间约 0.4 点」的来源，并判断哪条杠杆值得付全量成本。
> 协议：320、layer 2+3、legacy greedy k=2000、`--calib-ratio 0.3`、P99.5、`sigma=2`、`split-seed 42`、seed 0、timm `racm_in1k`。
> 所有数字为 MVTec test 上的 development 结果，不构成 holdout 结论。

## 1. 结论

| 杠杆 | 5 类/15 类均值 | 判定 |
|---|---:|---|
| PCA-1024（train patch 拟合） | +0.18 点（5 类） | 无效，不上全量 |
| `unfold_pool`（3x3 展开后池化到 1024，仿官方 MeanMapper） | +0.13 点（5 类） | 无效，不上全量 |
| **`crop` + zoom 1.144（短边 366 -> 中心裁 320）** | **+0.71 点 image / -1.07 点 pixel**（15 类） | image 有效但 pixel 退化，**不设为默认** |

一句话：**描述子维度不是瓶颈（PCA 与官方式池化都只值 0.1~0.2 点）；几何视野是瓶颈，但它换来的是 image 分数上升、定位（pixel）下降的交换。**

## 5. 机制

crop-zoom 把视野缩小 12.6%、每格覆盖的原图像素从 3.2 px 降到 2.8 px：小缺陷（牙刷刷毛、螺纹缺口）占的 patch 更多，image 分数由 `max` 触发得更稳；代价是边缘缺陷可能被裁掉、40x40 网格上的定位分辨率下降，所以 pixel/AUPRO 退化。

## 6. 为什么不设为默认

1. 15 类里 capsule −2.75 点、tile −0.83、cable −0.30，方向不一致；
2. pixel AUROC −1.07 点、AUPRO 未测但方向大概率同向；
3. 只跑了 1 个 seed；
4. 若要按类启用，就又回到「在 test 上挑类」的陷阱（本轮已多次自曝）。

## 7. 复现

```powershell
.venv\Scripts\python.exe tools\run_experiment.py --run-dir experiment_data\06_optimization\22_crop\screw_z1.144_seed_000 -- `
  --category screw --data MVTec\mvtech_anomaly_detection --size 320 --greedy 2000 `
  --calib-ratio 0.3 --thr-pct 99.5 --blur-sigma 2 --split-seed 42 --seed 0 `
  --weights torch_cache\wide_resnet50_2_timm.pth --preprocess crop --crop-zoom 1.144
```

## 8. 局限

- 单 seed、单 split；PCA/unfold 只覆盖 5 类；
- PCA 只试了 1024 维（等于不降维），未试 256/512；
- crop 的 pixel 退化未做 AUPRO 与掩码对齐的目视核查；
- 未与官方 IM224 在同一机器、同一天重跑（复刻数字来自 `18_replica`）。

## 9. 下一步（供决策）

- 若目标是「论文级 image AUROC」：只启用 crop-zoom 作为可选开关，报告两套数字，不合并；
- 若目标是「产线定位」：保持 stretch，把精力放在阈值/复核（已有 `docs/threshold-stability.md`）；
- 若要继续追官方 0.992：剩下的是 test 选型的 0.64 点与官方 ensemble，不建议再花算力。
