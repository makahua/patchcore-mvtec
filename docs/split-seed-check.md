# split-seed 敏感性复验（2026-11-06）

> 目的：回答「0.9791 / 0.9203 这组数字有多依赖 70/30 的那一次切分」。
> 配置：`2+3` / legacy greedy 2000 / P99.5 / σ=2 / 320 / timm `racm_in1k`；仅把 `--split-seed` 从 42 换成 123，其余不变。
> 数据角色：MVTec test 为 **development-only**，本文不是 holdout 结论。

## 1. 为什么只跑一组

90 run 配对基线（split-seed 42）的门槛判定中，第 4 条「单类退化 ≤ 0.03」FAIL（cable −0.0500、transistor AUPRO −0.2308），
因此**默认配置仍为 `2+3`**。既然最终配置与基线配置相同，`split-seed=123` 的 45 个 run 同时充当「基线复验」与「最终配置复验」。

## 2. 结果（15 类 macro，先逐 seed 求 macro，再取三 seed 均值 ± 样本标准差）

| 指标 | split-seed 42 | split-seed 123 | 差值 |

| image AUROC | 0.9791 ± 0.0010 | 0.9786 ± 0.0019 | -0.0005 |

阈值均值：见 `split_check.json` 的 `thr` 行（P99.5 是逐类分位数，绝对值随切分漂移）。

## 4. 判断

1. **切分本身贡献的波动**与 seed 波动同量级时，`split-seed=42` 的单点结论不能当作「这个方法就是 0.979」。
2. 逐类位移的方向如果与 90 run 的逐类强弱一致（screw/pill/toothbrush 偏低），说明排序稳定、只是绝对值漂。
3. 若某类在两种切分下都低于 0.93，才值得写进「已知短板」，而不是归因于切分运气。

## 5. 局限

- 只换了一个 split-seed，不是 5 折交叉；只能说「对这一次切分不敏感/敏感」，不能说「对切分无偏」。
- MVTec 的 train/good 只有 60–391 张，70/30 切分的组合空间有限，两次切分高度相关。
- 仍为单机单卡、单权重；AUPRO 来自 40×40 上采样双线性插值。

## 7. 按类配置（1+2）在 split-123 上的复核

主表改成按类配置（screw/capsule 用 `1+2`）后，这两类另在 split-123 上各跑三个 seed：

| 类别 | 配置 | split-42 image | split-123 image | split-42 漏检 | split-123 漏检 |
|---|---|---:|---:|---:|---:|
| screw | 2+3 | 0.9231 | 0.9279 | 36.4% | 57.7% |
| screw | 1+2 | 0.9737 | 0.9763 | 21.8% | 26.9% |
| capsule | 2+3 | 0.9823 | 0.9525 | 56.9% | 30.9% |
| capsule | 1+2 | 0.9904 | 0.9818 | 25.4% | 21.1% |

读法：**换层带来的提升在两个划分上都成立**（screw +4.8/+5.1 点，capsule +2.9/+0.8 点），
而漏检率的绝对值对划分极其敏感（同一配置能差 20 个点）——所以对外报漏检必须带划分信息，
且不能把单次划分的漏检当成产线承诺。
