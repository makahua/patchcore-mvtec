# 阈值口径与 conformal 统计保证

> 复核时间 2026-11-04（P0-2）· 数据源 `experiment_data/00_baselines/results_best/scores/*.json`
> 工具 `tools/conformal_threshold.py`（只需 numpy，不需要数据集 / GPU / 权重）

## 结论先说

1. 现有报表里的「目标过杀 0.5%」是**名义值**：取的是留出良品的 P99.5 经验分位，而每类只有 18–117 张标定良品，分位点本身带偏差、且无法量化。
2. 换成 split-conformal 后，**15 类没有一类能保证 0.5%**。保证水平上限是 `1/(n+1)`，要 0.5% 至少需要 **199 张**标定良品。
3. 真正可达的水平是 **0.85%（hazelnut，n=117）～5.26%（toothbrush，n=18）**，中位 1.37%；除 toothbrush 外都落在 0.85%–1.59%。
4. 同一批分数在这个口径下：macro 漏检 **21.3%**、macro 过杀 **2.93%**；经验分位口径是 20.0% / 3.10%。**结论方向不变，但「0.5% 过杀」不能再当承诺讲。**

## 1. 为什么经验分位不够

`np.percentile(cal, 99.5)` 在 n=18 时相当于用 18 个点估「第 0.09 个」观测，分位点落在最大值附近；n 越小，阈值越偏向 max(calib)，同时你**没有任何可报告的不确定性**。工业验收问的是「过杀率能不能压到 0.5%」，这需要一个有限样本的保证，而不是一个点估计。

## 2. split-conformal 的做法

给定目标水平 α 与 n 张标定良品分数：

```
k = ceil((n + 1) * (1 - α))
若 k > n  →  当前样本量下 α 不可达，最高只能保证 α_min = 1 / (n + 1)
否则       →  阈值 = 第 k 小的标定分数
```

在「标定良品与线上良品可交换（同分布）」假设下，该阈值满足 `P(良品分数 > 阈值) ≤ α`。可达性判据 `α ≥ 1/(n+1)` 等价于 `n ≥ 1/α − 1`，这就是第 3 节表格的来源。

实现见 `tools/conformal_threshold.py:conformal_quantile()` 与 `classify.py:conformal_quantile()`（两处逻辑一致：前者离线报表，后者进 build / report）。阈值用严格大于比较，因此与 `verdict()` 的 `score < thr_ok → OK` 对齐。

另用 Clopper-Pearson 单侧上界（95%）给出「观测到 k/n 次误报时真实误报率的上界」，用来判断 n 张测试良品能证明什么——n=20 时观测 0 次误报，真实过杀率上界仍有 13.9%，这解释了为什么小测试集上也别宣称 0.5%。

## 3. 需要多少标定良品

| 目标过杀 α | 最少标定良品 `ceil(1/α − 1)` | 本仓库 15 类中可达的类数 |
|---|---|---|
| 5% | 19 | 15 / 15 |
| 2% | 49 | 14 / 15（toothbrush n=18 不可达） |
| 1% | 99 | 1 / 15（仅 hazelnut n=117） |
| **0.5%** | **199** | **0 / 15** |
| 0.2% | 499 | 0 / 15 |

## 5. 要在 MVTec 上真正做到 0.5%，缺多少良品

| 类别 | train/good 总数 | 需要 calib 比例（199 张） | 可行性 |
|---|---|---|---|
| hazelnut | 391 | 0.51 | 可以，但建库只剩 ~190 张 |
| screw | 320 | 0.62 | 勉强 |
| carpet / grid / pill | 264–280 | 0.71–0.75 | 建库样本被压得很薄 |
| cable / capsule / metal_nut / transistor / bottle | 209–224 | 0.89–0.95 | 建库几乎无图可用，不可行 |
| toothbrush | 60 | 3.32 | 物理上不可能 |

所以 0.5% 在这个数据集上不能靠调 `--calib-ratio` 解决，只有三条路：

1. **诚实报可达水平**（本文做法）：对外说「良品过杀 ≤ 1/(n+1)，本批标定样本对应 0.85%–5.26%」。
2. **扩标定样本**：跨批次 / 跨工位 / 跨班次采集良品，只用于标定、不进记忆库（工业现场通常做得到，MVTec 做不到）。
3. **降评分方差**：top-k 均值替代 max、多尺度融合、或对分数做单调校准（等距回归），让同样的样本量估出更稳的工作点。

## 6. 对现有报表的影响

- `classify.py report` 默认口径**不变**（经验分位，兼容旧结果）；加 `--conformal` 才切换，并逐类打印「撑不起 0.5%，实际可达 x%」。
- 全 15 类在 α=0.5% 下（conformal）：汇总良品过杀 0.2%、良品进灰区 1.7%、漏检 21.3%、总复核量 23.5%；经验分位口径为 0.2% / 2.1% / 20.0% / 22.7%。差异不大，但 conformal 的阈值系统性地更高（等于 max(calib)），所以漏检多 1.3 个点——这正是「名义 0.5% 其实没做到」的具体代价。
- 面试口径一句话：「0.5% 是我们的目标工作点，但 18–117 张标定图只能给出 1/(n+1) 级别的保证，可达水平 0.85%–5.26%；要真的压到 0.5% 需要 ≥199 张独立良品，这在 MVTec 上做不到，我们把它写成限制而不是粉饰。」

```powershell
# 1) 离线统计：0.5% 档，逐类给出可达水平与 CP 上界（只需 numpy）

# 2) 换档：看 5% / 2% / 1% / 0.2% 各有多少类可达
```
